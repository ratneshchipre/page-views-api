## Introduction

Welcome to the official documentation of **Page Views API**.

Page Views API is an open-source, lightweight solution to track how many times a page is visited &ndash; without complex setup or dashboards.

It provides:

- Simple integration via a script tag
- Automatic page tracking (including SPAs)
- Privacy-friendly deduplication
- Fast and reliable view counts

## Usage

Follow the steps below to start tracking page views and retrieving counts.

<Steps>

<Step>Add Tracking Script</Step>

The easiest way to integrate Page Views API is by adding the tracking script to your website.

```html
<script
  src="https://page-views-api.ratneshc.com/script"
  data-site="example.com"
  defer
></script>
```

What this does

- **Automatic Path Detection** - Detects the current page using `window.location.pathname`.
- **SPA Support** - Tracks route changes automatically in frameworks like React, Next.js, etc.
- **Reliable Tracking** - Uses `navigator.sendBeacon / fetch` with `keepalive` to ensure requests complete.
- **Lightweight** - No dependencies. Minimal performance impact.

<Step>Fetch View Count</Step>

You can retrieve the total number of views for a specific page or entire site.

### Endpoint URL

```bash
GET https://page-views-api.ratneshc.com/api/v1/views?site=example.com&path=/
```

### Query Parameters

| Parameter | Type     | Required | Description                      |
| --------- | -------- | -------- | -------------------------------- |
| `site`    | `string` | Yes      | Unique identifier for your site. |
| `path`    | `string` | No       | Page path (defaults to `/`).     |

### Example

```typescript
const res = await fetch("https://page-views-api.ratneshc.com/api/v1/views?site=example.com&path=/");

const data = await res.json();

console.log(`Total views: ${data.views}`);
```

### Displaying Views in UI

```tsx
import { useEffect, useState } from "react";

export default function ViewCounter() {
  const [views, setViews] = useState<number | null>(null);

  useEffect(() => {
    fetch("https://page-views-api.ratneshc.com/api/v1/views?site=example.com&path=/")
      .then(res => res.json())
      .then(data => setViews(data.views));
  }, []);

  return (
    <span className="inline-flex items-center px-2 py-1 text-sm rounded-md border">
      {views ?? "..."} views
    </span>
  );
}
```

### Example Response

```json
{
  "views": 1234
}
```

</Steps>

## How It Works

- A request is sent whenever a page is loaded
- The API identifies the visitor using a hashed identifier
- Duplicate views are ignored within a time window
- View counts are stored and updated in real time

## Deduplication & Privacy

To prevent inflated numbers, we use a privacy-friendly deduplication mechanism:

- **Deduplication Window:** A visitor is counted only once every **30 minutes** per page.
- **Privacy First:** We don't store IP addresses. Instead, we generate a short-lived **SHA-256 hash** of the visitor's IP and User Agent to identify unique sessions.

## Rate Limiting

To maintain performance and prevent abuse, the API is rate-limited:

- **Limit:** 60 requests per minute.
- **Scope:** Based on the client's IP address.
- **Automatic Normalization:** Our API automatically handles protocol removal, lowercasing, and trailing slash normalization for both `site` and `path`.
- **Failures:** Requests exceeding the limit will receive a `429 Too Many Requests` response.

## Error Handling

The API uses standard HTTP status codes:

| Status | Code                    | Description                                                 |
| ------ | ----------------------- | ----------------------------------------------------------- |
| `400`  | `Bad Request`           | Missing or invalid query parameters (e.g., missing `site`). |
| `429`  | `Too Many Requests`     | You have exceeded the rate limit.                           |
| `500`  | `Internal Server Error` | Unexpected server error.                                    |

Error Response Format:

```json
{
  "error": "Missing or empty required query parameter: site"
}
```
